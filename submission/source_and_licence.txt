DATA SOURCES AND LICENCES
=========================

1. BIRD text-to-SQL benchmark (all questions, hints, gold SQL and databases)
   Website:  https://bird-bench.github.io/
   Paper:    Li et al., "Can LLM Already Serve as A Database Interface? A BIg Bench for Large-Scale
             Database Grounded Text-to-SQLs", NeurIPS 2023 Datasets and Benchmarks.
   Licence:  CC BY-SA 4.0 (https://creativecommons.org/licenses/by-sa/4.0/). Redistribution is allowed with
             attribution and under the same licence; the BIRD files and everything derived from them in this
             submission are therefore shared under CC BY-SA 4.0.

   original/bird/   Unchanged BIRD dev files (release dev_20240627, https://bird-bench.oss-cn-beijing.aliyuncs.com/dev.zip),
                    reduced to the five databases the project uses:
                      test:              formula_1, student_club
                      harness tuning:    superhero, toxicology, california_schools
                    dev.json and dev_tables.json keep only the entries of these databases; dev_databases/<db>/
                    is copied as released (SQLite file + database_description CSVs).
                    Script that downloads the full release: code/scripts/download_bird.py

   BIRD train split (NOT included, several GB). Used only to build the LoRA training pairs, which ARE included.
                    Download https://bird-bench.oss-cn-beijing.aliyuncs.com/train.zip, unpack to code/data/bird_train,
                    then: python scripts/build_training_data.py --bird-dir data/bird_train --out data/training
                    (needs Node.js for Cube; see code/docs/README_technical.md).

2. Processed data created in this project (derived from BIRD, CC BY-SA 4.0)

   processed/splits/test_ids.json      332 BIRD dev question ids (formula_1 + student_club), frozen before any experiment
   processed/splits/tune_ids.json      120-question subset of the tuning databases (early harness versions)
   processed/test_questions.jsonl      the 332 test questions: question, hint ("evidence", hidden from the model in
                                       all reported results), gold SQL (the expected output; answers are checked by
                                       executing it and comparing rows)
   processed/tune_questions.jsonl      all 363 questions of the three tuning databases (harness development), same fields
   processed/lora_training/<adapter>/  chat-format LoRA training and validation files, exactly as fed to
                                       code/scripts/train_lora.py; written by code/scripts/make_sft.py (seed 13;
                                       validation = 3 whole held-out training databases, see split.json):
                                         lora_full         "LoRA, full prompt"     (code/training_data)
                                         lora_lean         "LoRA, lean prompt"     (code/training_data, --profile lean)
                                         lookup_lora_full  "lookup LoRA, full prompt" (code/training_data_sv3)
                                         lookup_lora_lean  "lookup LoRA, lean prompt" (code/training_data_sv3, --profile lean)
                                         noschema_lora     "noschema LoRA" (only if synthetic/ is present)
   processed/synthetic/synth.jsonl     (if present) template questions about the two test schemas, generated by
                                       code/scripts/synth_schema_qa.py from the schemas and sampled values; no BIRD
                                       dev question, hint or SQL is used

   Kept inside code/ because the code reads them from there (not duplicated here):
   code/training_data*/verified.jsonl  3,531 BIRD train question -> Cube query pairs, each kept only if the Cube
                                       query returns the same rows as BIRD's gold SQL; schemas/ = schema texts
   code/cube/model/*.yml               generated Cube semantic-layer models of the five dev databases
   code/results/runs/*.jsonl.gz        model outputs of every reported run (one line per question)

3. Models (NOT included)
   Qwen2.5-Coder-7B-Instruct and -14B-Instruct, Apache 2.0, https://huggingface.co/Qwen
   Served 4-bit (Q4_K_M) through Ollama (qwen2.5-coder:7b, qwen2.5-coder:14b).
